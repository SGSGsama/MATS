# Upgrade notes

v1.1.0 reduces fresh child Task specs while preserving the full first-launch Role Contract, exact packet/delivery identity, role precedence, drift recovery, remote-evidence handling and mechanical gate. Every role has a regression budget; Owner packets project only global/current-WP commitments and accepted upstream semantics, while raw accepted-result refs remain Guard pins instead of model drill-down inputs. Review, Planner and side-role contexts retain their existing compact projections. Control directly answers from user/control state or verified summaries; only an answer needing new domain evidence uses the new `mats query` -> `mats answer` path. It reuses the retained Owner without a packet, fresh init, candidate or delivery form, verifies one response, rejects duplicate pending questions, and returns `OWNER_ANSWER_READY`. Ordinary work through fresh dispatch, continuation or steer always requires its mechanical gate and one `worker_done`; terminal prose is not delivery.

v1.0.2 accepts Orca's exact settled context-only cleanup receipt: `state=retained`, `reason=no_owned_resource`, `processAction=none`, with the requested Dispatch ID. This receipt means the Dispatch owns no terminal resource to close; it is a successful authority cleanup, not an unconfirmed release. MATS records that cleanup, stops projecting the settled Owner as a workspace writer, reports that the pre-existing terminal was retained, and completes guarded acceptance. Other `retained` receipts and mismatched Dispatch IDs remain rejected.

v1.0.1 restores the persisted fixed role catalog identity `fixed-semantic-v17`. Product SemVer and the internal task-state contract have independent lifecycles; upgrading MATS must not rename an existing `.task/config/policy.yaml` catalog or require migration of otherwise valid project state. This patch fixes the `invalid fixed role catalog` regression introduced in v1.0.0 without rewriting user task data.

v1.0.0 is the first stable SemVer release. It removes blind Control waits after irregular worker shutdown. `mats wait --control` performs a nonblocking Run-mail probe and checks the fresh active bound-Dispatch set before it blocks. With neither, it returns the current deterministic `advance` state immediately. During a real wait it watches all relevant active Dispatches, not only compact Owner continuations. A successful current same-session context completion may auto-resume; fresh/reviewer/failed/stopped/cancelled settlement without delivery returns `BLOCKED/LIFECYCLE_DELIVERY_MISSING`, while a delivery imported by another waiter returns current state. Pure question/escalation deliveries are acknowledged after capture and cannot loop; a batch containing `worker_done` is acknowledged only after its staged results import. Global packet order distinguishes an obsolete attempt from a newer unimported continuation, so `advance` cannot surface the older blocked result while the replacement delivery is pending. The one pre-block notice is emitted only when blocking actually starts. No persistent lock, manual lifecycle file, duplicate init prompt or old compatibility path was added.

The semantic delivery boundary now distinguishes data by content instead of leaking a generic YAML parser error. A generated TSV remains the only model-authored delivery input and is canonicalized to YAML in place. Ordinary checksum/index files are pinned as individual evidence even if placed in an `evidence_manifest` row; only a YAML file carrying the script-owned MATS manifest marker is expanded recursively. `.task` result/review citations are materialized as content-addressed `memo_source` refs rather than domain evidence. Generated forms state the closed Owner status set and reject native `succeeded` as a semantic status before transaction work. This fixes the exact p000083 failure without asking Control to hand-convert TSV/YAML or hashes.

v17.8 closes the no-delivery continuation gap. `mats wait --control` now combines lifecycle mail with silent, bounded checks of only the newest current same-session context-only Owner Dispatch. A queued `worker_done`/question/escalation wins; otherwise exact native completion with a confirming empty peek is an internal continuation signal, and `advance` reuses the same Codex session with the compact delta/role/Control recap. It does not depend on TUI idle state, expose a new recovery flag, treat completion as a result, resume fresh/replaced/old/already-imported work, or require the user to wake Control. Owner `--actor-packet` waits remain event-only and the outer 20-minute checkpoint semantics are unchanged.

Control provenance IDs are now content-addressed (`control-<receipt-digest>`) instead of keyed only by the host session. A Control session may survive a Skill update, so the same session can legitimately acquire a new role-contract digest without overwriting or colliding with its immutable prior receipt. Existing `control-<session>` refs remain readable. Managed actions reject a stale Control contract with an exact `mats activate` recovery.

Compact same-Owner delivery uses the bound Codex session ID as its sole durable index. Each continuation re-enumerates the current connected/writable handle, creates a plain context Dispatch, sends the exact instruction/delta/role+Control recap with compact lifecycle IDs once, then sends a pure Enter. It no longer calls same-terminal `worker-start` or `dispatch --inject`, so `agent_unconfigured`/`no_agent_detected`, old handles, user-takeover labels and runtime epochs cannot block a live session. Before creating a new Task it reconciles ready/dispatched MATS retries by immutable packet digest, fences stale idle context-only dispatches without closing the Owner, settles superseded ready Tasks, and reuses the newest exact Task. Already-running exact work is bound without duplicate input. Only session absence permits a fresh full launch. Empty deltas stay inline. Owners persist through locally possible work instead of using `failed` as a checkpoint. `OWNER_RESULT_NOT_CANDIDATE` stops Control automation; a Control-level resume uses `advance --resume-owner`, never forwards user text, and requires locally executable remaining work to continue through implementation and verification instead of returning another progress-only checkpoint. `mats steer` is only for Owner-directed in-scope adjustments to an active dispatch; it verifies that dispatch's bound Codex session/workspace and directly wakes the current terminal rather than relying on an unread orchestration inbox.

The installed Skill now keeps all semantic orchestration strategies but exposes `mats dispatch` as the only managed child-launch command. Model and effort remain fixed and are resolved and verified by code; callers never supply them.

The model-facing CLI is actor-scoped. `mats activate` combines the isolated doctor check with current-Control receipt refresh, and `mats bootstrap` accepts one semantic goal file while deriving the Orca Run and bootstrap transaction. Low-level transaction primitives are rejected through the installed launcher. Old-version compatibility is not a normal branch. `TASK_MIGRATION_REQUIRED` only stops/reports; after an explicit user migration instruction, the last-resort `mats migrate` performs read-only layout/ref/hash validation and returns a manual guide only on failure.

New packets inject `mats deliver <packet-id>` and `mats evidence <packet-id> ...`. Both derive packet digest, delivery path and assigned workspace from canonical bindings. Side-request forms no longer require a model-supplied caller-session value. Migration does not execute or translate old packet contracts.

Native admission is now closed inside MATS. `dispatch`, `accept` and `apply-plan` automatically start Orca once if needed, capture a compact current-Run view, resolve current worktree/access and overwrite the fixed diagnostic view. Control no longer checks or supplies `runtime-view.yaml`, calls raw `orca open/status`, inspects processes, or diagnoses permission context from a missing file.

Dispatch success output is now a compact state-machine projection. It no longer echoes the full injected prompt, fixed binding, launch argv or raw native receipts into Control context.

`mats advance` is now the normal post-bootstrap progression interface. It shares Guard/routing predicates, imports staged completions, runs R0, routes reviews and source-backed repair/Synthesis/Planner work, applies valid Planner output, and performs proven Owner release plus acceptance. It stops after at most one new dispatch or with structured `WAIT`/`READY`/`NEEDS_DECISION`/`BLOCKED`/`DONE`; Control interprets only the semantic decision state, never diagnostic strings. A new WP Owner requires explicit `-cyber` or `--non-cyber`, while derived roles inherit the packet classification. Default local work is bounded to 16 steps, and `--dry-run` has no packet/task/delivery/state side effects.

Control now marks cybersecurity dispatches with `-cyber`. Sol-bound Synthesis/R2 launches use `gpt-daybreak-blue-latest` with unchanged effort, and automatically retry Sol only after an explicit model-unavailable response. The packet and normalized receipt preserve the classification and fallback attestation.

Installation moved out of the Skill payload. Run root `install.cmd --force` to stage a fresh copy in the configured Codex skills directory, build its destination-local `.venv`, install `installer/requirements.txt`, self-check it, and replace the previous installation only after staging succeeds.

The copied Skill no longer contains the installer, requirements, vendored PyYAML, generated bytecode, or the unused Python admission wrapper. Existing strategy references, role contracts, schemas and semantic guards remain.

Role identity is now two-layered: fixed `owner_role` remains the authority/model key, while optional `specialty` carries an arbitrary descriptive domain persona. Existing plans without `specialty` remain valid and receive deterministic `domain-research`/`domain-engineering` fallbacks.

Fresh launches inline the complete structured Role Contract. A healthy same-WP `--continue-owner` uses exact instructions, a content-addressed packet delta, current delivery/gate identity and a role/Control recap; it does not repeat the full packet or fresh MATS init. The launcher reacquires the terminal by Codex session ID and current workspace, not old dispatch/handle metadata. Only session absence returns to a fresh full prompt. Managed waits require either `--control` or `--actor-packet`; their `resume_anchor` restores role/WP/run/plan context and limits stale Owner packets to returning to Control. Verified checkpoints/completions carry no mandatory reread; semantic events and drift retain exact refresh paths.

Control loading and all later decisions are now deterministic: the activation files have a fixed order and EOF markers; workflow, role, cyber, delegation, review and Planner selection use closed tables with STOP outcomes for missing or ambiguous evidence. `storage.md` and `native-boundary.md` remain trigger-loaded. Command flags come from `mats <command> -h`; reading `scripts/*.py` to infer usage is prohibited.

The Script/Control boundary is now closed over named MATS control-artifact commands. Product tests, benchmarks, reproducers, traffic generators and remote commands remain Owner work regardless of size, cost or read-only status. Combined test/diagnose/fix/retest work reuses one Engineering Owner; Luna Aux cannot replace it. Approval-gated external mutations are asked by that Owner and relayed unchanged by Control.

Evaluation accounting now requires cumulative Control-session usage alongside child dispatches and attributes every actually loaded MATS/Orca context event. These context tokens remain inside Control input totals and are never added twice. A missing Control session, missing Orca load, partial context observation or unknown cost makes the managed total unknown. A separate footprint command measures UTF-8 source bytes only for prompt-growth diagnosis.

`mats dispatch` now exposes digest-pinned retry for an already-bound packet whose every prior native dispatch is confirmed `failed` in its automatically refreshed view. Retry creates a fresh native Task from the exact stored packet and placement and does not call packet issue. It rejects missing prior bindings, non-failed/unknown delivery, changed name/operation/WP/request/instructions/cyber, and continuation reuse. Admission occurs before replacement of the packet delivery form while the coordinator mutex prevents local state races, so an admission-rejected retry preserves the existing draft byte-for-byte. Planner-output Guard repair remains a separate mechanically generated fresh repair request.

`config/policy.yaml` is no longer part of Control activation or refresh. It remains installed as script-private execution configuration and is validated by doctor/Guard/dispatch. Control treats semantic `policy_ref` values as opaque provenance. Policy-dependent R2 routing is exposed through stable `reason_code=R2_REQUIRED`; human-readable error wording is not a routing API.

Every dispatch now starts from a script-generated semantic draft. Packet-bound `deliver` derives the binding/workspace, materializes schema/identity fields, exact candidate snapshot and evidence hashes/versions, then validates before native report/`worker_done`. `evidence` bundles many files behind one recursively checked reference, and model packets omit transaction-heavy receipts/hash lists. A check failure stays in the same worker session and never authorizes dispatch retry.

Runtime evidence is no longer confused with a plan-contract change. `scope.paths` bounds writes; `scope.refs` and packet evidence are reading advice rather than permissions. A role reads task-relevant sources without a grant. Candidate snapshots cover only `scope.paths`, so unrelated tracked/untracked workspace additions never stop a WP. Historical `scope.refs` pins are plan provenance, not candidate gates; cited current inputs are pinned separately. No Control command, Planner occasion, plan/version change or user question is involved. For genuine Planner changes, the finalizer expands compact nested `scope.refs` paths and schema `oneOf` failures expose branch-level causes.

Snapshot identity no longer includes host `stat()` mode bits, which differ between Windows Python and POSIX/Git Bash for the same checkout. Git binary worktree/index identities cover tracked changes; untracked content remains path/hash pinned. Admission and semantic commits now share one OS-released `coordinator.lock` rather than two visible lock carriers. Native launch remains inside admission serialization until Orca exposes a reservation/fencing protocol that can reconcile unknown outcomes safely.

Control no longer needs hand-written refs or completion receipts for normal transitions. `wait` normalizes `worker_done` and returns top-level `next_operation: advance`; per-binding `result` remains exact recovery. Generic Orca `reportPath` metadata is never read or used as a MATS file selector. Child prompts point to the exact packet, defer optional payloads, avoid routine native-guide loading, and reload only when the returned anchor or actual context loss requires it. A missing/contradictory public recovery is now a tool-bug STOP, never authority for Control to edit the Skill or bypass Guard.

Leaf dispatches now classify themselves as execution/review rather than Orca coordination. The real injected worker preamble was verified to include exact identity/capability plus worker_done, heartbeat, ask, escalation, check and post-completion behavior. Children never load `orchestration`; `orca-cli` is permitted once only as the final syntax fallback after at least two compactions and failed exact subcommand help.

Control now reads only transition-named MATS semantic/control state for routing. It cannot inspect product source, raw logs/evidence or worker transcripts to perform diagnosis, tests or implementation inference. A user test request, added log or in-scope behavior correction first resumes the viable same-WP Owner unchanged; protocol/API/architecture vocabulary is not a Planner trigger. Direct user steering reaches Planner only when it explicitly supersedes a cited current project/plan field, otherwise the Owner/reviewer must produce `plan_conflict`.

All fresh role prompts and compact Owner continuations now direct workers to ask for the exact required-but-unavailable remote evidence through the native preamble. They neither fabricate it nor misreport its absence as a Guard/tool failure, and non-required evidence creates no question.

Normal `advance` closes a completion batch mechanically; direct `result <binding-id>` is its exact recovery primitive. After every batch result is imported, MATS releases every R1/R2/Planner/Luna/Synthesis dispatch in that batch, persists each release confirmation, then persists the single FIFO acknowledgement and removes tmp. Research/Engineering Owners remain retained. Release/ack failure leaves the exact staging and skips already-confirmed mutations on retry, so Control neither enumerates terminals nor remembers cleanup state.

Planner request authoring is now explicitly non-design authority. Control preserves immutable user/source text and may add MATS-required structure, cited materialized-state facts and explicit authority limits only. It must ask a neutral decision question and cannot turn ambiguous terms into protocol/frame formats, architecture, implementation, compatibility/fallback, testing or acceptance choices; those remain Planner decisions.

Transient orchestration exchange now has one location: `.task/tmp`. Workers receive one exact `tmp/deliveries/<packet-id>.yaml` and cannot write elsewhere under `.task`; MATS alone writes completion staging and cleans it after successful import/acknowledgement. Initial planning uses the single `bootstrap` entry; old multi-command bootstrap paths are removed.

Control path resolution is now pinned to the active host workspace via explicit `--repo` on every MATS call. Shell CWD, prior directory visits and host temp provide no write authority; Control-generated logs, captures and redirects reuse fixed files only under that repository's `.task/tmp`.

Control read scope is now pinned too: unrelated Runs/workspaces in native inventory remain opaque and cannot be enumerated as substitute repositories. A missing Git HEAD stops for explicit baseline/path direction. Normal MATS calls no longer trigger duplicate `orca-cli` plus full-guide loads. The installer now gives payload copies installation-time mtimes and states that existing Control sessions cannot hot reload a replacement. A Windows directory lock first receives bounded retry; a persistent live-session pin falls back to file-atomic payload replacement with backup/rollback and revalidation of the retained isolated runtime.

Bootstrap authoring is mechanical: Control writes one UTF-8 goal under `.task/tmp`, then `bootstrap` creates valid seed project/plan YAML, a compact Git inventory, the Planner request, semantic state and the current fixed Control receipt. Old `init`, receipt-file attachment and staged bootstrap commands are removed.

Long-lived records are now namespaced by milestone (`.task/m0_<slug>/...`, `.task/m1_<slug>/...`) instead of accumulating in project-global typed folders. The current `plan_id` selects new-write placement. Top-level legacy refs/directories require explicit manual migration; normal reads do not adapt them. Planner requests may pin `target_milestone_id`; Guard enforces one-step numbering and changes the namespace mechanically. Packet names are automatic six-digit indexes, while bindings/results/reviews retain their required dispatch/digest keys.

Owner continuity is explicit and mechanically supported. Research or Engineering stays in the same WP session across candidate, correctable blocked/failed results, R0/R1/R2, Synthesis return and local repair. `dispatch --continue-owner` derives the current candidate/latest result and compact delta, then reacquires the exact Codex session's current handle; `external`/`user-takeover`, old dispatch and detector labels never release or replace it. Only authoritative session absence permits a fresh full launch. Normal shutdown occurs only after every required review passes and Guard proves live writer release is the sole acceptance blocker. Separately, a valid Planner proposal may retire only affected proven Owners after the same proof; unaffected Owners remain live. Fresh one-shot Planner/reviewer/side roles remain ephemeral.

Transaction-heavy role exchanges use generated TSV forms. `deliver` and request finalizers create canonical YAML and all schema/identity/ref/hash/version/snapshot fields. Runtime Planner requests use `planning-request-form`; Control preserves directive text and supplies only semantic cells. Planner repair is a constrained prefilled edit of the exact rejected proposal.

Immutable bindings now carry script-derived role/WP/reason/mode/source attribution; unavailable provider usage is explicitly unknown and workers write no monitoring report. Continuation deltas use stable-key object changes for repeated review/downstream collections rather than resending the entire changed list, and artifact enumeration parses each YAML once. These are static reductions only: no token, cache, billing or latency saving is claimed until measured from real provider usage and profiles.
